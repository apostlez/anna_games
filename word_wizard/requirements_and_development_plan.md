# Word Wizard 요구사항 및 개발 계획

- 문서 상태: Draft
- 문서 버전: 1.0
- 원본 PRD: [prd.md](prd.md)
- 목표 배포 주소: `https://apostlez.github.io/anna_games/word_wizard/`
- 대상 플랫폼: 데스크톱 및 모바일 최신 브라우저

## 1. 제품 개요

### 1.1 제품명

**Word Wizard**

### 1.2 한 줄 설명

마법사가 되어 날짜별 영어 단어를 읽고, 쓰고, 선택하며 파닉스와 단어 연상을 반복 학습하는 브라우저 게임이다.

### 1.3 사용자 스토리

> 나는 영어 단어와 파닉스를 복습해야 한다. 마법 수업에 참여해 단어를 소리 내어 읽고, 들은 단어를 쓰고, 한국어 뜻에 맞는 영어 단어를 선택하면서 재미있게 반복 학습하고 싶다.

### 1.4 학습 목표

| 학습 입력 | 사용자의 확인 행동 | 적용 게임 |
|---|---|---|
| 영어 스펠링 | 말하기, 한국어 의미 확인 | 마법 주문 외치기 |
| 한국어 의미 및 단어 듣기 | 영어 스펠링 쓰기, 발음 듣기 | 마법책 쓰기 |
| 한국어 의미가 적힌 쪽지 | 영어 스펠링 선택, 의미 확인 | 빗자루 비행 |

### 1.5 제품 차별점

기존 영어 퀴즈 서비스의 반복 문제 풀이를 마법책, 가고일, 파이어볼, 빗자루 비행이라는 짧은 게임 루프로 바꾼다. 각 모드는 같은 단어 데이터를 서로 다른 회상 방식으로 사용하므로 단순 암기보다 인출 연습을 유도한다.

## 2. 범위

### 2.1 MVP에 포함할 기능

- 타이틀 화면과 마법사·탑 콘셉트의 대표 이미지
- 시작 후 마법책을 펼치는 전환
- 학습 날짜 선택
- 세 가지 학습 모드 선택
- 게임 선택 화면에서 날짜별 완료 상태 확인
- 날짜별 세 가지 게임 완료 상태 저장
- 선택한 날짜의 전체 활성 단어 진행
- 100점 만점 점수 계산
- 공통 종료 버튼
- 영어 단어 음성 재생
- 브라우저 마이크를 이용한 영어 발음 인식
- 마이크 권한 거부 또는 음성 인식 미지원 시 재시도 안내
- Supabase에서 날짜별 단어 데이터 읽기
- 음성 파일이 없을 때 브라우저 음성 합성으로 발음 재생
- 결과 화면, 점수, 복습 단어 표시
- GitHub Pages 정적 배포

### 2.2 MVP에서 제외할 기능

- 회원가입, 로그인, 멀티플레이어, 실시간 대전
- 학습자별 서버 진도 동기화
- 서버에 녹음 파일 저장
- 자동 발음 점수의 정밀한 음소 분석
- 별도 관리자 웹 화면
- 게임 중 광고, 결제, 외부 소셜 기능
- 원본 사운드북 페이지의 무단 자동 수집

제외 기능은 기본 게임 루프가 안정화된 뒤 별도 제품 요구사항으로 분리한다.

## 3. 확정할 기본 정책

PRD에서 구현 방식이 열려 있는 항목은 아래 기본값으로 시작한다. 실제 구현 전에 바꾸려면 이 문서와 테스트 기준을 함께 갱신한다.

| 항목 | MVP 기본 정책 |
|---|---|
| 기술 스택 | Phaser 4, Vite, JavaScript ES modules |
| 렌더링 | Phaser 캔버스 중심, 메뉴·입력·상태 안내는 접근성을 위해 HTML 오버레이 병행 |
| 단어 선택 | 선택한 날짜의 활성 단어만 사용 |
| 날짜 데이터 최소 수 | 모든 모드와 보기 생성을 위해 날짜별 활성 단어 3개 이상 필요 |
| 문항 수 | 선택한 날짜의 전체 활성 단어를 사용 |
| 점수 | 날짜 단어 수를 N이라 할 때 첫 시도 정답 `100/N`점, 두 번째 시도 정답 `50/N`점, 오답 0점 |
| 음성 인식 재시도 | 마법 주문 외치기에서 최대 3회 |
| 쓰기 모드 재시도 | 한 문항 1회. 오답 후 페이지 소멸 연출을 하고 다음 문항으로 이동 |
| 빗자루 비행 문제 | 현재 단어 또는 한국어 뜻 중 하나를 무작위로 표시 |
| 정답 판정 | 소문자화, 양끝 공백 제거, 유니코드 정규화, 구두점·하이픈 정리 후 비교 |
| 음성 재생 우선순위 | 준비된 영어 음성 파일 → 브라우저 `speechSynthesis` |
| 음성 인식 | 브라우저 `SpeechRecognition` 또는 `webkitSpeechRecognition` |
| 로그인 | MVP에서는 없음. 점수·최근 진행은 브라우저 로컬 저장 |
| 데이터 실패 | Supabase 조회 실패 시 검증된 번들 시드 데이터로 개발·데모 실행 |
| 결과 탑 | 빗자루 비행에서 해당 날짜의 전체 단어를 만점으로 맞히면 큰 탑, 그 외에는 점수에 비례한 작은 탑 |
| 날짜 완료 기준 | 같은 날짜의 세 가지 게임을 모두 결과 화면까지 완료 |
| 완료 상태 저장 | MVP에서는 브라우저 `localStorage`에 저장하며 계정·기기 간 동기화는 하지 않음 |

점수 계산에서 `N`은 세션 시작 시 고정한 선택 날짜의 활성 단어 수다. 문항별 배점의 합을 반올림해 최종 점수를 표시하며, 모든 단어를 첫 시도에 맞히면 단어 수와 관계없이 100점이 된다.

## 4. 사용자 흐름

```text
TitleScene
  -> Start
GameSelectScene
  -> 완료 날짜 및 게임별 상태 확인
  -> 날짜 선택
  -> 게임(마법) 선택
SpeakSpellScene / WriteSpellScene / BroomFlightScene
  -> 선택 날짜의 전체 단어 완료
ResultScene
  -> 진행 상태 저장
  -> 같은 게임 다시 하기 / GameSelectScene / 처음으로
```

### 4.1 진입

1. 사용자가 목표 URL에 접속한다.
2. 초기 로딩이 끝나면 타이틀, 탑 배경, 지팡이와 책을 든 오리지널 마법사, `Start` 버튼을 표시한다.
3. 단어 데이터 조회가 늦어져도 타이틀 화면은 먼저 표시한다.
4. 필수 데이터가 준비되지 않은 경우 시작 시점에 원인을 알기 쉬운 오류 메시지를 표시한다.

### 4.2 게임 선택 및 완료 날짜 확인

1. `Start`를 누르면 마법책이 펼쳐지는 전환을 보여준다.
2. `GameSelectScene`은 Supabase의 활성 단어에서 날짜 목록을 중복 없이 가져오고, 날짜별로 `미완료` 또는 `완료` 상태를 표시한다.
3. 각 날짜에는 마법 주문 외치기, 마법책 쓰기, 빗자루 비행의 세부 완료 상태와 저장된 점수를 표시한다.
4. 세 가지 게임을 모두 결과 화면까지 완료한 날짜만 `완료` 날짜로 표시한다. 정답률이나 점수가 100점인지 여부는 날짜 완료 조건이 아니다.
5. 최신 날짜를 기본 선택하되 사용자가 다른 날짜를 선택할 수 있다.
6. 이미 완료한 날짜도 다시 선택할 수 있으며, 완료 상태를 지우지 않고 게임을 재플레이할 수 있다.
7. 선택한 날짜에 활성 단어가 3개 미만이면 게임 선택을 막고 데이터 준비 상태를 안내한다.
8. 날짜가 선택되면 세 가지 게임 카드를 표시하고, 각 카드에 게임 이름, 학습 행동, 입력 장치, 완료 상태, 최근 점수를 표시한다.
9. 선택한 게임에 맞는 게임 씬을 시작한다.

### 4.3 종료

- 타이틀을 제외한 설정·게임·결과 화면 우측 상단에 `Exit` 아이콘 버튼을 둔다.
- 게임 중 종료를 누르면 진행 중인 문항을 잃는다는 확인을 한 번 표시한다.
- 확인하면 현재 세션을 정리하고 타이틀 화면으로 돌아간다.
- 취소하면 현재 게임을 그대로 재개한다.
- 브라우저 뒤로 가기나 새로고침은 복구 대상이 아니며, 사용자가 잃게 되는 진행 상태를 안내할 수 있다.

## 5. 상세 기능 요구사항

### 5.1 공통 요구사항

| ID | 요구사항 | 완료 기준 |
|---|---|---|
| FR-COM-01 | 모든 게임은 선택한 날짜의 단어 세트로 시작해야 한다. | 세션 시작 후 문항 단어가 다른 날짜에서 섞이지 않는다. |
| FR-COM-02 | 세션은 선택한 날짜의 모든 활성 단어를 제공해야 한다. | 해당 날짜의 마지막 단어 완료 후 결과 화면으로 이동한다. |
| FR-COM-03 | 점수는 단어 수와 관계없이 100점 만점이어야 한다. | 날짜 단어 수를 N이라 할 때 문항 배점 합계가 0~100 범위다. |
| FR-COM-04 | 문항별 진행 상태를 보여줘야 한다. | 현재 번호와 전체 문항 수, 현재 점수를 확인할 수 있다. |
| FR-COM-05 | 성공·실패 피드백을 시각과 소리로 제공해야 한다. | 사운드가 켜진 경우 정답·오답 피드백이 재생되고, 꺼진 경우에도 시각 피드백은 남는다. |
| FR-COM-06 | 모든 게임 화면에 종료 버튼이 있어야 한다. | 설정, 세 가지 게임, 결과 화면에서 종료 동작을 수행할 수 있다. |
| FR-COM-07 | 마지막 문항 뒤 결과 화면을 보여줘야 한다. | 총점, 정답 수, 복습 단어와 다음 행동을 표시한다. |
| FR-COM-08 | 사용자의 사운드 선호를 기억해야 한다. | 음소거를 켜면 이후 씬에서도 효과음·발음이 재생되지 않는다. |
| FR-COM-09 | 터치와 마우스를 모두 지원해야 한다. | 모바일 탭과 데스크톱 클릭으로 동일한 주요 흐름을 수행할 수 있다. |
| FR-COM-11 | 날짜별 세 게임의 완료 상태를 선택 화면에서 확인할 수 있어야 한다. | 각 날짜에 전체 완료 상태와 세 게임별 완료 상태가 표시된다. |
| FR-COM-12 | 세 게임을 모두 완료한 날짜를 저장해야 한다. | 세 게임이 모두 결과 화면까지 끝나면 해당 날짜가 완료로 저장된다. |
| FR-COM-13 | 완료 상태는 재방문과 새로고침 뒤에도 유지되어야 한다. | 같은 브라우저에서 선택 화면을 다시 열어도 날짜·게임별 상태와 점수가 복원된다. |

### 5.2 마법 주문 외치기

**학습 목적:** 보이는 영어 스펠링을 정확히 읽고 의미와 연결한다.

1. 화면 정면에서 가고일이 접근한다.
2. 펼쳐진 스펠북에 현재 영어 단어를 크게 표시한다.
3. 마이크 아이콘은 `대기`, `듣는 중`, `판정 중`, `성공`, `다시 시도`, `사용 불가` 상태를 구분한다.
4. 사용자가 마이크 버튼을 누르면 영어 음성 인식을 시작한다.
5. 인식 결과를 정규화해 정답 단어 또는 허용된 변형과 비교한다.
6. 정답이면 지팡이에서 파이어볼이 발사되고 가고일이 물러난다.
7. 정답 직후 한국어 뜻을 표시하고 영어 발음을 재생한다.
8. 날짜 단어 수를 N이라 할 때 첫 시도 정답은 `100/N`점, 두 번째 시도 정답은 `50/N`점, 세 번째까지 실패하면 0점이다.
9. 오답이면 인식된 결과와 재시도 안내를 표시한다. 세 번째 실패 후 정답과 뜻을 보여주고 다음 문항으로 이동한다.
10. 선택 날짜의 전체 단어 완료 시 축하 메시지와 최종 점수를 표시한다.

**음성 인식 예외 처리**

- 브라우저가 음성 인식을 지원하지 않거나 마이크 권한을 거부하면 원인을 안내하고 다시 시도할 수 있게 한다.
- 인식 결과가 빈 문자열이면 오답으로 확정하지 않고 짧은 재시도 안내를 표시한다.
- 인식 원문이나 녹음 파일은 MVP에서 서버로 업로드하지 않는다.

### 5.3 마법책 쓰기

**학습 목적:** 들은 단어와 한국어 뜻을 영어 스펠링으로 회상한다.

1. 스승님의 음성으로 현재 단어를 들려준다.
2. 영어 정답은 처음부터 표시하지 않는다.
3. 한국어 뜻과 필요하면 파닉스 힌트를 표시한다.
4. 사용자는 화면에 표시된 영어 글자 타일을 순서대로 선택해 스펠링을 완성하고 제출한다.
5. 제출 버튼은 `다 썼다`로 표시하고, 누르면 책장이 넘어가는 약 0.68초 애니메이션을 재생한다.
6. 페이지 넘김 중에는 글자 타일과 제출·삭제 버튼을 잠시 비활성화한다.
7. 애니메이션이 끝나면 책 이미지는 다음 문항 화면으로 교체되어 조작을 가리지 않아야 한다.
8. 정답이면 책이 빛나고, 오답이면 해당 페이지가 사라지는 피드백을 재생한다.
9. 오답 후에는 올바른 스펠링과 한국어 뜻을 표시하고 다음 문항으로 이동한다.
10. 선택한 글자가 없으면 제출하지 않고 선택 안내를 유지한다.
11. 사운드가 켜져 있으면 문항 시작 시 단어를 재생하고, 결과 후에도 정답 발음을 한 번 재생한다.

### 5.4 빗자루 비행

**학습 목적:** 한국어 의미를 영어 스펠링과 연결하고 빠르게 선택한다.

1. 빗자루를 탄 마법사가 진행하는 길과 갈림길을 표시한다.
2. 현재 단어 또는 한국어 뜻 중 하나를 무작위 문제로 표시한다.
3. 문제가 단어이면 선택지에 뜻 3개를, 문제가 뜻이면 선택지에 단어 3개를 표시한다.
4. 정답 1개와 선택한 날짜의 다른 단어에서 무작위 오답 2개를 구성한다.
5. 정답을 선택하면 앞으로 날아가며 해당 단어의 만점 배점 `100/N`을 획득한다.
6. 오답을 선택하면 잘못된 길 연출과 공통 오답 효과음을 보여주고 0점으로 처리한 뒤 다음 갈림길로 이동한다.
7. 문항 종료 후 정답 단어와 뜻을 짧게 보여주고 공통 정답 효과음과 발음을 재생한다.
8. 선택 날짜의 전체 단어를 모두 맞히면 큰 탑에 도착한다.
9. 하나라도 틀리면 점수에 맞는 작은 탑에 도착하고 결과를 표시한다.
10. 결과 화면에는 전체 단어 수 대비 정답 수, 총점, 도착한 탑 등급을 표시한다.
11. 빗자루 이미지는 게임 영역 중앙에 크게 표시하고, `BROOM FLIGHT` 텍스트는 영역 하단에 작게 표시한다.

### 5.5 결과 화면

- 축하 문구와 총점 `0~100`을 크게 표시한다.
- `전체 단어 수 중 정답 수`와 모드 이름을 표시한다.
- 틀린 단어, 사용자가 입력한 답, 올바른 답, 한국어 뜻을 복습 목록으로 제공한다.
- 다음 행동을 제공한다.
  - 같은 날짜·같은 게임 다시 하기
  - 같은 날짜에서 다른 게임 선택
  - 날짜 및 게임 선택 화면으로 돌아가기
  - 타이틀로 돌아가기
- 결과 화면에서도 `Exit` 버튼은 타이틀로 돌아가는 동작을 수행한다.
- 결과 화면에 진입하면 해당 날짜·게임의 완료 상태, 완료 시각, 점수, 정답 수를 `localStorage`에 저장한다.
- 완료한 게임을 다시 플레이해도 기존 완료 상태를 미완료로 되돌리지 않는다.
- 서버 저장과 계정·기기 간 동기화는 로그인 요구사항이 확정된 뒤 추가한다.

### 6.2 데이터 품질 규칙

- `study_date`별 `active = true` 단어가 3개 이상이어야 한다.
- 세션은 해당 날짜의 활성 단어를 일부만 잘라 쓰지 않고 전체 사용한다.
- 빗자루 비행을 위해 각 날짜·레벨 그룹에는 보기 생성에 필요한 단어가 3개 이상 있어야 한다.
- `word`, `normalized_word`, `meaning_ko`는 빈 문자열을 허용하지 않는다.
- 정답 비교용 문자열은 import 시점에 생성하고 클라이언트에서도 동일한 규칙으로 재계산한다.
- 같은 날짜에 동일한 `normalized_word`가 중복되면 import를 실패시킨다.
- 음성 파일이 없더라도 단어 데이터는 활성화할 수 있지만 브라우저 음성 합성 fallback을 제공해야 한다.
- 학습자에게 노출할 단어와 뜻은 원본 사용 권한을 확인한 자료만 등록한다.

### 6.3 Supabase 사용 정책

- PRD에 제공된 프로젝트 URL은 `SUPABASE_URL` 환경 값으로 사용한다.
- 클라이언트에는 Supabase의 공개 `anon` 키만 포함한다. `service_role` 키는 절대 정적 배포물에 넣지 않는다.
- MVP의 공개 테이블 조회는 `active` 단어에 한정한다.
- 테이블 insert/update/delete 정책은 관리자 또는 별도 로컬 import 절차에만 허용한다.
- 단어 데이터에 개인 정보나 음성 녹음을 저장하지 않는다.
- 실제 RLS 정책은 Supabase migration 파일로 버전 관리한다.

### 6.5 날짜별 게임 진행 상태

MVP는 로그인 없이 브라우저별 진행 상태를 `localStorage`에 저장한다. 저장 키는 `word-wizard-progress-v1`로 고정한다.

```json
{
  "dates": {
    "2026-09-30": {
      "speak": {
        "completed": true,
        "score": 80,
        "correctCount": 9,
        "wordCount": 10,
        "completedAt": "2026-09-30T12:00:00.000Z"
      },
      "write": {
        "completed": false,
        "score": 0,
        "correctCount": 0,
        "wordCount": 10,
        "completedAt": null
      },
      "flight": {
        "completed": true,
        "score": 100,
        "correctCount": 10,
        "wordCount": 10,
        "completedAt": "2026-09-30T12:20:00.000Z"
      },
      "completed": false,
      "completedAt": null
    }
  }
}
```

- `speak`, `write`, `flight`는 각각 마법 주문 외치기, 마법책 쓰기, 빗자루 비행을 뜻한다.
- 게임 결과 화면에 도달한 경우에만 해당 게임의 `completed`를 `true`로 저장한다.
- 세 게임의 `completed`가 모두 `true`가 되면 날짜의 `completed`를 `true`로 저장한다.
- 날짜 완료 여부는 점수와 무관하며, 세 게임의 결과 화면 도달 여부로만 결정한다.
- 선택 화면은 저장 데이터가 없어도 모든 날짜를 `미완료`로 표시한다.
- 손상되거나 이전 버전인 저장 데이터는 무시하고 빈 진행 상태로 시작한다.
- 저장 데이터에는 단어 원문이나 음성 녹음을 넣지 않는다.

## 7. 음성 및 오디오 요구사항

### 7.1 발음 재생

1. `audio_url`이 있으면 해당 파일을 우선 재생한다.
2. `audio_start`와 `audio_end`가 있으면 HTML Audio의 재생 위치를 해당 구간으로 제한한다.
3. 구간 메타데이터가 없거나 파일을 불러오지 못하면 `window.speechSynthesis`로 영어 음성을 재생한다.
4. 가능한 경우 `en-US` 음성을 선택하고, 음성 목록이 늦게 준비되는 브라우저를 고려한다.
5. 모바일 브라우저의 자동 재생 제한을 피하기 위해 첫 재생은 사용자의 클릭·탭 이후에 시작한다.
6. 재생 중인 단어는 재생 버튼으로 다시 들을 수 있다.
7. 음소거 상태에서도 텍스트와 애니메이션은 정상 진행한다.

### 7.2 음성 인식

- 우선 API: `SpeechRecognition` 또는 `webkitSpeechRecognition`
- 인식 언어: `en-US`
- 마이크 버튼을 누르면 5초 동안 음성을 녹음하고, 녹음 창이 끝난 뒤 최종·중간 인식 결과를 합쳐 판정한다.
- 마이크 권한 거부, 마이크 없음, 무음, 네트워크, 시작 실패는 원인 안내와 재시도로 처리한다.
- 기본 설정: 최종 결과만 판정하고, 중간 결과는 상태 표시용으로만 사용
- 한 문항의 최대 청취 시간과 무응답 timeout을 설정한다.
- 오류 종류를 `권한 거부`, `지원하지 않음`, `네트워크`, `빈 결과`, `알 수 없음`으로 나누어 사용자 메시지를 달리한다.
- 발음의 세밀한 음소 점수는 MVP에서 제공하지 않고, 인식 텍스트가 정답과 일치하는지만 판정한다.
- 녹음 데이터는 저장·전송하지 않는다. 브라우저와 선택한 음성 인식 구현의 개인정보 정책을 배포 문서에 명시한다.

## 8. 게임 상태 및 화면 설계

### 8.1 Phaser 씬 구성

| 씬 | 책임 |
|---|---|
| `BootScene` | 기본 설정, 저장된 사운드 선호 불러오기, 다음 씬 시작 |
| `PreloadScene` | 이미지·효과음·폰트·로컬 fallback 데이터 로드, 로딩 표시 |
| `TitleScene` | 탑 배경, 마법사, 타이틀, Start 버튼 |
| `GameSelectScene` | 마법책 펼침 연출, 날짜 선택, 날짜·게임별 완료 상태, 게임 선택, 데이터 준비 상태 |
| `SpeakSpellScene` | 가고일, 스펠북, 마이크 상태, 음성 판정, 파이어볼 |
| `WriteSpellScene` | 교사 음성, 책 페이지, 글자 타일, 성공 빛·오답 소멸 연출 |
| `BroomFlightScene` | 빗자루 이동, 한국어 쪽지, 갈림길 보기, 탑 도착 연출 |
| `ResultScene` | 점수, 복습 목록, 완료 상태 저장, 재시작·게임 변경·타이틀 이동 |
| `OverlayUIScene` 또는 DOM overlay | Exit, 사운드, 진행률, 접근성용 상태와 입력 컨트롤 |

씬 사이의 데이터는 명시적인 세션 객체를 `scene.start`의 전달 데이터 또는 전역 registry로 공유한다. 씬을 직접 서로 강하게 참조하지 않는다.

### 8.2 세션 객체

```js
{
  studyDate: "2026-09-30",
  mode: "speak | write | flight",
  words: [],
  currentIndex: 0,
  attempts: [],
  score: 0,
  soundEnabled: true,
  startedAt: 0
}
```

단어 원본을 변경하지 않고 문항별 결과를 별도 기록한다. 결과 화면은 `attempts`에서 복습 목록을 만든다.

### 8.3 화면 공통 UI

- 우측 상단: Exit, 사운드 토글
- 상단 또는 하단: `문항 3 / 10`, 현재 점수
- 중앙: 현재 학습 대상과 상호작용 컨트롤
- 하단: 짧은 상태 메시지와 재생·제출 버튼
- 작은 화면에서는 글자 타일과 버튼이 겹치지 않도록 세로 배치한다.
- 마이크, 사운드, 종료 아이콘은 아이콘만 사용하지 않고 접근성 이름을 제공한다.
- 애니메이션은 `prefers-reduced-motion`을 존중하고, 시각 효과가 꺼져도 결과 판정은 동일해야 한다.

```text
Create an original fantasy educational game title illustration for a browser game called Word Wizard.
Show a friendly young wizard standing in front of a tall stone tower at dusk, holding a wooden wand in one hand and an open spellbook in the other, ready to pronounce a spell.

```

생성 결과는 원본 파일을 그대로 게임에 넣기 전에 배경 제거, 크기 통일, 모바일 해상도 테스트, 라이선스 기록을 완료한다.

### 10.3 책임 분리

- 씬은 화면 연출과 사용자 입력을 조정한다.
- `word-repository`는 Supabase와 seed fallback을 숨긴다.
- `answer-normalizer`는 모든 모드가 공유하는 정답 비교 규칙을 소유한다.
- `scoring`은 UI나 Phaser에 의존하지 않는 순수 함수로 작성한다.
- `speech-service`는 음성 인식 API의 지원 여부와 오류를 표준 상태로 바꾼다.
- `audio-service`는 파일 재생, 음성 합성, 음소거 상태를 관리한다.
- `local-storage`는 날짜별 세 게임 완료 상태, 점수, 정답 수, 완료 시각을 저장·복원한다.
- 세션 객체는 씬 간 전환에서 유지할 데이터만 가진다.

### 10.4 Phaser 구현 원칙

- 새 프로젝트이므로 Phaser 4 API를 기준으로 작성한다.
- 씬 전환은 `this.scene.start`, `this.scene.launch`, `this.scene.pause` 등 ScenePlugin을 통해 수행한다.
- 씬의 `init`, `preload`, `create`, `update` 생명주기를 역할별로 지킨다.
- 가고일·파이어볼처럼 실제 충돌이 필요한 요소는 Arcade Physics를 사용한다.
- 정적 배경이나 애니메이션이 필요 없는 이미지에는 Image를, 프레임 애니메이션이 필요한 요소에는 Sprite를 사용한다.
- 타이머와 음성 이벤트는 씬 종료 시 정리해 이전 문항의 콜백이 다음 씬에 영향을 주지 않게 한다.
- 점수 판정은 프레임 속도나 애니메이션 완료 여부에 의존하지 않는다.

## 12. 테스트 및 검증 계획

### 12.1 단위 테스트

- 답안 정규화
  - 대소문자 차이
  - 앞뒤 공백
  - 하이픈과 아포스트로피
  - 유니코드 정규화
  - 허용 변형 답안
- 점수 계산
  - 첫 시도 정답 `100/N`점
  - 두 번째 시도 정답 `50/N`점
  - 오답 0점
  - N이 7 또는 11이어도 전체 첫 시도 정답은 100점
  - 점수 계산 결과 반올림 후 0~100 범위
- 문항 선택
  - 중복 단어 없음
  - 선택 날짜 필터 유지
  - 빗자루 보기 중 정답 정확히 1개
  - 단어 부족 시 명확한 오류
- 데이터 validation
  - 필수 필드 누락
  - 중복 단어
  - 잘못된 날짜·레벨
  - 존재하지 않는 오디오 경로
- 진행 상태
  - 게임 하나만 완료하면 날짜는 미완료
  - 세 게임을 모두 완료하면 날짜는 완료
  - 재플레이해도 완료 상태가 미완료로 바뀌지 않음
  - 새로고침 후 날짜·게임별 상태와 점수 복원
  - 손상되거나 이전 버전인 저장 데이터 무시

### 12.2 브라우저 흐름 테스트

### 12.3 성능 및 안정성

- 일반적인 데스크톱과 모바일 에뮬레이션에서 게임 플레이 중 60 FPS를 목표로 한다.
- 한 씬에 불필요한 오브젝트와 타이머를 누적하지 않는다.
- 게임 종료·재시작을 여러 번 반복해 이전 음성 이벤트와 콜백이 남지 않는지 확인한다.
- 이미지와 오디오의 총 용량을 측정하고 모바일 초기 로딩을 지연시키는 큰 파일을 분리 로드한다.
- 네트워크가 끊겨도 이미 로드된 현재 문항은 완료할 수 있어야 한다.

## 13. 배포 계획

### 13.1 로컬 명령

```bash
npm install
npm run dev
npm run test
npm run build
npm run preview
```

### 13.2 GitHub Pages

- Vite의 `base`를 상대 경로 `./`로 설정한다.
- production build 결과를 게시 저장소의 `anna_games/word_wizard/` 경로에 반영한다.
- 배포 후 브라우저 개발자 도구에서 JS module, 이미지, 오디오 요청이 404가 아닌지 확인한다.
- 환경 변수에 의존하는 Supabase 클라이언트 값은 공개 anon 키만 사용하고, 배포 전 RLS를 다시 확인한다.
- 음성 인식은 HTTPS 환경에서 테스트한다. GitHub Pages는 HTTPS를 제공하므로 마이크 권한 테스트가 가능하다.

### 13.3 데이터 배포

- 개발 단계에서는 `seed.words.json`으로 화면과 게임 로직을 먼저 검증한다.
- Supabase migration을 적용한 뒤 검증된 단어 데이터를 import한다.
- 날짜별 단어 수, 중복, 뜻 누락, 오디오 접근성을 배포 전 검사한다.
- 단어 출처와 사용 권한 기록은 코드 저장소 또는 별도 내부 문서에 남긴다.
